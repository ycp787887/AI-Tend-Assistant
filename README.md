# 智能招标文件分析助手

> 帮投标员把翻标书的2小时缩短到10分钟

---

## 一、这个项目解决了什么真实问题？

现实翻标书太痛苦：
- 一份标书几十页，要手动找资质要求、截止时间、废标条款
- 不同平台（广联达、政采云）操作流程不一样，经常搞错
- 扫描件PDF不能复制文字，只能肉眼一点点看

我用AI+Python做了一个工具，上传标书就能自动提取关键信息、扫描风险条款。

**当前状态**：已上线Streamlit Cloud，待试用中。

---

## 二、技术栈（就这些，每个我都真正用过）

| 用途 | 用了什么 | 为什么选它 |
|------|----------|------------|
| 界面 | Streamlit | 最快速度做出可用的界面 |
| AI能力 | DeepSeek API | 便宜（1块钱能分析几十份标书） |
| 提取文字 | pypdf / Tesseract OCR | 普通PDF用pypdf，扫描件用OCR |
| 存储 | SQLite + 本地缓存 | 分析过的文件存起来，第二次秒出 |
| 加密处理 | pikepdf | 有些标书有密码锁，本地解开不上传 |

## 三、踩过的坑（每个都是真实遇到的）

### 坑1：扫描件OCR后，程序崩了

**遇到的情况**：上传扫描件PDF，OCR识别出了文字，但点“开始分析”按钮，程序报错 `UnicodeDecodeError`。

**我怎么排查的**：打印文件头，发现OCR后把纯文本写回了原文件变量，程序检测到文件头不是`%PDF`就报错。

**我怎么解决的**：加了一个标记 `ocr_done = True`，如果已经OCR过，就直接当文本处理，不再检测文件头。一共加了10行代码。

**结果**：扫描件PDF也能正常分析了。

---

### 坑2：上传文件后，侧边栏的按钮消失了

**遇到的情况**：文件上传成功，但侧边栏里的“开始分析”按钮不见了，用户没法继续操作。

**我怎么排查的**：逐行删代码，发现删到第二个`with st.sidebar:`块时，按钮回来了。

**我怎么解决的**：查Streamlit文档才知道，后一个`with st.sidebar:`会覆盖前一个的内容。把两个侧边栏块合并成一个。

**结果**：按钮稳定出现。

---

### 坑3：OCR跑完后，页面跳回了第一步

**遇到的情况**：用户选了“已有招标文件”，上传扫描件，OCR跑完页面刷新，选项被重置成了“还没报名”，刚上传的文件也丢了。

**我怎么排查的**：查代码发现`st.radio`的`key="bidding_stage"`没有在`session_state`里初始化。

**我怎么解决的**：在初始化函数里加了一行 `"bidding_stage": "已有招标文件"`。

**结果**：页面刷新后状态保留。之后我把所有交互组件都统一在初始化函数里赋值。

## 四、正在填的坑（面试官问过的）

### 面试官问：“真实标书的表格跨页、手写体污染怎么办？”

我当时答不上来，因为第一版只测了干净文档。**现在正在解决**：

| 问题 | 怎么解决 | 当前效果 |
|------|----------|----------|
| 表格跨页断裂 | 用`camelot`提取所有页表格，用`pandas`按行合并 | 测试5份真实标书，还原率从62%提到89% |
| 手写体/盖章污染 | 用OpenCV做图像预处理（二值化+去细线） | 字符识别率从60%提升到85%（实验性） |

**代码已跑通**（一个20行的独立小工具），下一步集成到主项目。

## 五、我学到了什么

1. **先让东西能用**：第一版就是个单文件，能跑就行，后面有问题才拆模块。
2. **不是所有问题都要用AI**：平台指引、文件格式检测这些，if/else比AI更稳更快。
3. **踩坑笔记比架构图更能证明能力**：上面三个坑的修复过程，比任何“技术亮点”都有说服力。
